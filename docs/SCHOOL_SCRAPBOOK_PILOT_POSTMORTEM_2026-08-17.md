# Разбор пилота `school-scrapbook`

Дата: 2026-08-17.

Цель документа — не описать внешний вид школьного шаблона, а зафиксировать все проблемы, обнаруженные после его первого перевода в продукт, и автоматические барьеры, которые не позволят повторить их в следующем шаблоне.

## Что теперь означает «шаблон зарегистрирован»

Регистрация считается завершённой только если один профиль `universal-v1` одновременно:

- виден в ателье и проходит private/public, desktop/mobile и Story/Post/A4;
- присутствует в generated registry и dispatcher;
- после `availability: "product"` автоматически появляется в каталоге, выбранной карточке, заставке, preview черновика, private/public и админке;
- использует один renderer и один resolver ассетов без продуктовых веток по `templateId`;
- создаёт публичный payload актуальной версии;
- отдаёт Story/Post/A4 и PDF без битых изображений;
- проходит `npm run template:launch-check` и реальный smoke на тестовой открытке.

Одна запись в registry без этих условий больше не называется готовой продуктовой регистрацией.

## С какими проблемами столкнулся пилот

| Область | Что произошло после регистрации | Причина | Защита для следующего шаблона |
|---|---|---|---|
| Качества в экспорте | Плашки растягивались, затем после сохранения пропорций стали слишком мелкими | Web-ассет использовался в фиксированной экспортной сетке | Декларативные `exportQualityCards`, общий preset и проверяемая схема `2–1–2` |
| Геометрия декора | Правка глобуса и рюкзака для скачивания сдвинула Web-версию | Web и export использовали одни координаты | Раздельные слои `visibleOn: desktop/mobile/export`; launch-gate рендерит все поверхности из одного профиля |
| Header Story | Текст и имя переносились не так, как в ателье | Форматное правило появилось только в export renderer | Переносы имени и описания теперь общие и не зависят от ID шаблона |
| Подписи фотографий | Один текст имел разный размер в ателье, private/public и экспорте; после увеличения перестал помещаться | Разные формулы масштаба и постоянное применение `minScale` | Общий text-capacity preset; `minScale` применяется только около лимита; тесты одинакового scale |
| Подложки экспорта | В Story возникали чёрные области, затем подложки исчезли во всех форматах | Браузер ателье передавал сырой `/templates/...` URL, а ImageResponse не мог стабильно обработать WebP и query crop/slice | Единый `resolveTemplateExportAsset`, `/api/template-export-asset`, browser-baseline запрещает сырые template URL и битые изображения |
| Деформация ассетов | Рюкзак в подвале и верхний декор растягивались или обрезались | Контейнер заполнялся без сохранения естественного aspect ratio; crop/slice не исполнялся | `Decor` сохраняет aspect ratio, crop/nine-slice/horizontal-slice выполняются сервером и проверяются в Story/Post/A4 |
| Расхождение ателье и продукта | В открытке результат отличался от ателье, хотя профиль был один | Продукт и ателье использовали разные asset pipeline и скрытые ветки по ID | Общий renderer/resolver; launch-gate запрещает ID-ветки в shared runtime; ателье — источник истины |
| Каталожная миниатюра | В одном месте была новая иконка, в окне выбора оставалась бумажная | Preview брался из разных справочников и fallback | `cardTemplates` строится из регистрации, preview берётся только из `profile.metadata.preview`; gate сверяет его с manifest и реальным файлом |
| Preview черновика | После выбора школьного шаблона открывался технический/legacy preview | Preview route выбирал renderer не через общий dispatcher | Все поверхности используют `dispatchTemplateRenderer`; gate проверяет регистрацию и renderer |
| Геометрия private | Обложка занимала весь экран, необязательные блоки исчезали вместо предупреждения | Новый renderer не повторял продуктовый structural contract Route | Общий layout preset `route-v1`; baseline покрывает private/public и шесть схем на desktop/mobile |
| Заставка | Использовалась скучная универсальная миниатюра, затем школьный вид был зашит по ID | Intro не имел декларативного preset и собственных лёгких ассетов | `intro.preset`, `intro.kicker`, `intro.decor` находятся в профиле и автоматически попадают в заставку |
| Имя получателя | Имя с отчеством не делилось на две строки; mobile-кегль был мал | Не было общего правила ёмкости имени | Общий name-capacity preset: два слова — две строки, отдельная mobile-шкала, тесты предельного имени |
| Дата события | Дата не сохранялась, после reload обнулялась и отображалась на день раньше | Поле не входило в полный save/read contract; календарная дата проходила через UTC | Автосохранение, date-only parser без UTC и repository/UI tests |
| Финальная подпись | Не сохранялась и не попадала в открытку | Поле отсутствовало в одном из write/read/view-model переходов | Полный persistence contract и тесты формы, repository и renderer |
| AI-фразы и цитаты | После новых поздравлений старые результаты блокировали передачу; повторная генерация могла быть недоступна | Stale AI-блок считался отсутствующим; внешний provider мог быть недоступен | Существующий stale-результат даёт предупреждение, но не блокирует передачу; отсутствие результата остаётся блокировкой; provider failure обрабатывается отдельно |
| Доступность шаблона | Тестовую открытку нельзя было передать: «доступен только в ателье» | `availability: studio` использовался как продуктовая блокировка уже созданной тестовой карточки | Единая проверка `isProductTemplateId`; перевод в product выполняется только после gate, без локальных allowlist |
| Публичный черновик | Создание падало на `public_card_shares_payload_version_check` | Код и схема БД поддерживали разные версии payload; migration не была применена локально | Repository тест актуальной версии, миграция при `npm run dev` и при старте production-контейнера |
| Публичная версия | Текст header и шрифты отличались от ателье | Данные и typography проходили разными путями | `public.heroDescription` и typography берутся из профиля; public входит в browser-baseline |
| Скачивание | Story, Post, A4 и PDF поочерёдно падали | Ошибки проявлялись только в реальном raster pipeline | Browser-baseline Story/Post/A4, route tests, asset-transform tests и обязательный реальный smoke четырёх URL |
| Админка | Строки были пустыми, дата `Invalid Date`, действия вели на 404, нельзя было выдать бесплатный доступ старой открытке | Неполная repository projection и неправильные URL/временной фильтр | Repository/page tests, прямой переход в открытку и выдача/отзыв бесплатного private-доступа |
| Повторные ручные правки | После product-регистрации продолжалось движение координат в JSON | Не было формального visual freeze и launch-gate | Геометрия замораживается в ателье до product; после product допускается исправление общего контракта, но не скрытая подгонка route |

## Автоматический launch-gate

Главная команда перед продуктовой регистрацией и после изменения `availability`:

```powershell
npm run template:launch-check
```

Она выполняет:

1. Проверку manifest, бюджетов, размеров и наличия всех ассетов.
2. Legacy-baseline, чтобы новый шаблон не сломал Paper и Route.
3. Universal browser-baseline для private/public, desktop/mobile, шести схем и Story/Post/A4.
4. Полный набор unit/integration/repository тестов.
5. Production build.

`template-launch-gate.test.tsx` дополнительно проверяет каждый зарегистрированный universal-профиль:

- ID профиля, registration, dispatcher и availability;
- автоматическое появление product-шаблона в `cardTemplates`;
- совпадение каталожного preview с `template.assets.json`;
- наличие и реальные размеры каждого профильного ассета, включая intro-декор;
- отрисовку Story/Post/A4 через transform-route;
- отсутствие строкового ID шаблона в shared product runtime.

Browser-baseline дополнительно требует для каждого экспортного формата:

- точный размер холста;
- page underlay и closing slice;
- отсутствие raw `/templates/...` изображений;
- наличие обработанных `/api/template-export-asset` изображений;
- отсутствие broken images и browser errors.

## Новый обязательный порядок запуска шаблона

1. `npm run template:new -- <template-id>` создаёт профиль со статусом `studio` и сразу добавляет его в ателье.
2. В ателье полностью настраиваются private/public, desktop/mobile, Story/Post/A4, preview и intro. Все различия хранятся в профиле или общем preset.
3. JSON ателье переносится в исходный профиль; выполняются asset optimization и `npm run template:launch-check` при статусе `studio`.
4. Пользователь принимает полную визуальную матрицу. После этого геометрия считается замороженной.
5. В registration меняется только `availability: "studio"` → `"product"`.
6. Повторно выполняется `npm run template:launch-check`. На этом прогоне gate обязан увидеть шаблон в продуктовом каталоге и заставке.
7. На локальной/стендовой БД создаётся одна реальная открытка: выбор шаблона, reload настроек, передача, public draft, private/public, четыре download URL, админский бесплатный доступ.
8. Только после успешного smoke commit можно выпускать.

## Что остаётся ручным

Автоматические проверки обнаруживают технические расхождения, но не могут решить, красиво ли расположен конкретный рисунок. Поэтому единственная ручная операция перед product — визуальная приёмка матрицы в ателье. После неё продукт не должен требовать повторного движения пикселей: если оно требуется, это дефект общего профиля/renderer/preset и исправляется сначала в ателье.
