ТЗ для Kimi: повторная корректировка карточек вариантов подарка
Цель

Исправить список вариантов подарка на вкладке «Выбор подарка». После предыдущей доработки карточки остались слишком высокими, внутри появилось много пустого пространства, меню ⋯ сместилось вниз, а статистика голосования пропала.

Нужно сделать карточки компактными, вернуть показатели голосования и сохранить текущую функциональность.

1. Карточки на десктопе

Каждый вариант должен отображаться одной компактной горизонтальной строкой:

[Фото] [Название, описание, цена, магазин] [Голоса] [Процент и полоса] [⋯]
Состав карточки

Слева направо:

Изображение товара.
Основная информация:
название;
короткое описание;
цена;
домен магазина.
Количество голосов:
крупное число;
подпись «голос», «голоса» или «голосов» с правильным склонением.
Результат:
процент;
горизонтальная полоса прогресса.
Кнопка меню ⋯.
Размеры

Ориентиры:

высота карточки: примерно 88–100 px;
изображение: 60–68 px;
вертикальные отступы внутри: 10–14 px;
расстояние между карточками: 8–10 px;
не использовать фиксированную большую высоту или min-height, создающую пустое пространство.

Пример возможной сетки:

grid-template-columns:
  68px
  minmax(0, 1fr)
  72px
  130px
  36px;

align-items: center;
gap: 12px;
padding: 12px 14px;
min-height: 0;
height: auto;

Это пример, а не обязательная реализация. Использовать существующие компоненты и токены проекта.

2. Убрать пустое пространство

Проверить текущую верстку карточки и убрать причины растягивания:

фиксированную высоту;
избыточный min-height;
justify-content: space-between, растягивающий элементы по вертикали;
абсолютное позиционирование меню относительно нижнего края;
пустые контейнеры от ранее удалённой статистики;
лишние вертикальные отступы.

Высота карточки должна определяться содержимым.

3. Вернуть статистику голосования

Не удалять из карточек:

количество голосов;
процент;
полосу результата.

Даже при отсутствии голосов показывать:

0
голосов

0%
[пустая полоса]

Полоса должна оставаться нейтральной при результате 0%.

Процент и количество голосов должны рассчитываться из существующих данных, без изменения backend-логики.

4. Положение меню ⋯

Кнопка ⋯ должна:

находиться справа;
быть выровнена по вертикальному центру карточки;
не прижиматься к нижнему краю;
иметь кликабельную область не менее 36 × 36 px;
использовать текущее меню действий;
не менять своё положение при длинном названии или отсутствии изображения.

Не использовать абсолютное позиционирование, если оно не требуется архитектурой компонента.

5. Ограничение текста

Чтобы длинные данные не увеличивали карточку:

название — максимум две строки;
короткое описание — максимум одна строка;
домен магазина — одна строка;
длинный текст обрезать через ellipsis;
цена и домен не должны переносить статистику или меню на новую строку.

Не выводить в списке полный текст, полученный при неудачном разборе страницы магазина.

6. Мобильная версия

Текущую мобильную композицию полностью не переделывать.

На мобильном сохранить карточку в две логические зоны:

[Фото] [Название и данные] [⋯]

[Количество голосов] [Процент и полоса]

Требования:

карточка не должна иметь большое пустое пространство;
меню находится в правом верхнем углу содержательной строки;
статистика остаётся видимой;
название — максимум две строки;
описание — максимум одна строка;
высота карточки определяется содержимым;
ширина соответствует остальным карточкам вкладки;
горизонтального скролла быть не должно.
7. Состояния

Проверить варианты:

товар с изображением;
товар без изображения;
длинное название;
длинное описание;
отсутствующая цена;
отсутствующая ссылка;
0 голосов;
один и несколько голосов;
максимальные шесть вариантов;
открытое меню ⋯.

Карточки одного списка должны выглядеть визуально одинаковыми по плотности.

8. Не менять

В рамках этой задачи не изменять:

добавление варианта;
редактирование варианта;
удаление;
изменение порядка;
логику голосования;
расчёт доступных участников;
модальные окна;
правую колонку;
backend и структуру данных;
внешний вид других вкладок.
9. Критерии приёмки

Работа принимается, если:

На десктопе все данные варианта помещаются в одну компактную горизонтальную карточку.
Внутри карточек нет заметной пустой области.
При трёх вариантах список занимает существенно меньше высоты, чем сейчас.
При шести вариантах список остаётся обозримым и не выглядит чрезмерно длинным.
Кнопка ⋯ находится справа по вертикальному центру.
Количество голосов, процент и полоса результата снова отображаются.
При 0 голосов показываются корректные нулевые значения.
Длинные названия и описания не ломают сетку.
Мобильная версия не имеет горизонтального скролла и лишней пустоты.
Существующие действия карточки продолжают работать.
Порядок выполнения

Сначала найти конкретную причину увеличенной высоты существующей карточки. Не переписывать весь раздел и не проводить общий рефакторинг.

После исправления проверить только:

десктоп;
мобильную ширину;
0 голосов;
шесть вариантов;
длинное название;
открытие меню ⋯.

В отчёте перечислить изменённые файлы и кратко указать, из-за какого CSS-свойства или контейнера карточки растягивались.
