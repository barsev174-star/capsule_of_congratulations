# Уведомления о новых обращениях

Обращение сначала сохраняется в таблице `support_requests` и сразу появляется в админке. В той же транзакции создаётся отдельная запись доставки письма. Поэтому временная ошибка Resend не приводит к потере обращения.

Основной адрес задаётся переменной `SUPPORT_NOTIFICATION_EMAIL`; если она не задана, используется `support@slovesto.ru`. Для отправки нужны рабочие `RESEND_API_KEY` и `EMAIL_FROM`.

Telegram включается только при наличии обеих переменных:

- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TELEGRAM_SUPPORT_CHAT_ID` — числовой id личного чата получателя.

Для личного чата недостаточно указать `@barsev174`: пользователь должен сначала открыть бота и нажать Start, после чего числовой chat id можно получить через Bot API `getUpdates`. Если Telegram не настроен, обращения продолжают сохраняться в админке и отправляться на email.

## Проверка после развёртывания

1. Применить миграцию `0030_support_notification_deliveries.sql` штатной командой проекта.
2. Добавить переменные в `.env.production` и пересобрать web-контейнер.
3. Отправить тестовое обращение через форму поддержки.
4. Проверить письмо, строку обращения и статус доставки в `/admin/support`.
5. Вручную проверить обработчик очереди:

```bash
cd /home/deploy/capsule
bash infra/scripts/send-support-notifications.sh
```

Ответ пустой очереди:

```json
{"claimed":0,"sent":0,"failed":0}
```

## Повторные попытки

После ошибки очередь повторяет отправку через 1 минуту, 5 минут, 30 минут, 2 часа и 6 часов, не более пяти попыток. Для обработки очереди установить cron раз в минуту:

```cron
* * * * * cd /home/deploy/capsule && bash infra/scripts/send-support-notifications.sh >> /var/log/capsule-support-notifications.log 2>&1
```

Неудачную доставку также можно запустить вручную кнопкой «Повторить» в админке. Повторная отправка email защищена idempotency key на стороне Resend.
