# Публичная открытка и экспорты

Этот документ описывает публичную версию переданной открытки и экспорт её разрешённого содержимого.

## Превью приглашения участника — опубликовано 26.08.2026

## Публичная ссылка

- Маршрут: `/share/{token}`.
- По ссылке доступны только данные, которые получатель выбрал для публичного показа: имя, повод, счётчики, качества, выбранные фотографии с публичными подписями и лучшие фразы.
- Личные поздравления, авторы, невыбранные фотографии и остальные приватные данные в публичный payload и экспорт не попадают.
- При отзыве ссылки публичная страница, медиа и экспортные маршруты становятся недоступны.

## Управление из приватной открытки

- Организатор создаёт и передаёт приватную открытку; управление публичной версией предназначено получателю, открывшему персональную ссылку `/gift/{finalSlug}`.
- `finalSlug` служит ключом доступа получателя к существующему редактору `/gift/{finalSlug}/share`. Отдельная organizer-сессия для этого сценария не используется.
- В декоративном footer приватной открытки активная версия показывает компактный статус «Публичная версия активна» и действие «Настроить публичную версию».
- Если версии ещё нет, footer показывает «Создать публичную версию». Для существующего черновика или ранее выключенной версии используется «Настроить публичную версию».
- Рядом всегда доступно «Создать такую же открытку»: действие создаёт новый черновик и никогда не раскрывает `manageToken` исходной открытки.
- Устаревшие действия благодарности и печати приватной открытки удалены. Отдельной карточки управления публичной версией после открытки больше нет; «Открыть ещё раз» остаётся самостоятельным действием после декоративного footer.
- На desktop две CTA располагаются в строку с первичным публичным действием; на mobile — вертикально, на всю ширину контентной области.

## Скачивание

Нижняя панель публичной открытки открывает диалог скачивания. Диалог показывает лёгкие карточки пропорций форматов и не вызывает серверный renderer до нажатия «Скачать». Реальные `<img>`-предпросмотры Story/Post/A4 запрещены: они незаметно запускают сразу несколько дорогих экспортов.

Доступны форматы:

| Формат | Результат | Назначение |
| --- | --- | --- |
| Story | PNG, 1080 × 1920 | Вертикальная история 9:16 |
| Post | PNG, 1080 × 1350 | Публикация 4:5 |
| Print | Одностраничный полноцветный PDF A4 | Печать |

Маршруты рендера:

- `/share/{token}/image/story`
- `/share/{token}/image/post`
- `/share/{token}/image/print`
- `/share/{token}/image/print?preview=1` — PNG-предпросмотр печатной версии.

## Production pipeline и ограничения

Полный путь запроса:

```text
PublicShareDownloadDialog
  → GET /share/{token}/image/{format}
  → основной Next.js process
  → отдельный export-worker на 127.0.0.1:3001
  → payload и локальные fonts/assets
  → UniversalTemplateExportCard или legacy ExportCard
  → ImageResponse / Satori / Resvg
  → PNG
  → для A4: Sharp JPEG + одностраничный PDF
```

Production-ограничения:

- запускается только выбранный формат;
- одновременно выполняется один export;
- второй запрос получает `429` и `Retry-After: 5`;
- worker запускается лениво с `nice -n 10`;
- renderer timeout — 75 секунд;
- proxy timeout — 82 секунды;
- client abort — 85 секунд;
- при proxy timeout worker останавливается и будет создан заново;
- изображения и fonts загружаются через внутренний origin, без публичного DNS round-trip;
- PT Sans, Caveat и статические начертания Inter читаются из `public/fonts`;
- `/api/template-export-asset` использует ограниченный in-memory cache и дедупликацию параллельных преобразований;
- временные export-файлы не создаются: результат передаётся из memory buffers.

Основной Next.js не должен выполнять Satori/Resvg. Изоляция worker обязательна даже при concurrency `1`, потому что rasterization является CPU-bound и может блокировать Node.js event loop.

## Этапное логирование

Каждый renderer-request получает `requestId`, `format` и `durationMs`. Успешный экспорт проходит этапы:

1. `export:start`;
2. `export:assets-loaded`;
3. `export:layout-rendered`;
4. `export:image-rendered`;
5. `export:file-created`;
6. `export:complete`.

Ошибки worker proxy пишутся как `export:proxy-failed`, ошибки renderer — как `export:failed` с названием этапа. Если запрос не дошёл до `export:assets-loaded`, нужно проверять PostgreSQL/Docker DNS и общую нагрузку VPS, а не только Satori.

Клиент читает текст серверной ошибки, показывает понятное сообщение и в `finally` всегда возвращает кнопку из «Подготовка файла» в «Скачать».

## Правила экспортного макета

- Экспортные композиции реализуются в `src/app/share/[token]/image/[format]/route.tsx` и не изменяют разметку публичной страницы `/share/{token}`.
- Во всех форматах используются те же бумажные и полароидные ассеты, что и в публичной открытке.
- Рукописный Caveat используется для имени, названий разделов и подписей полароидов; PT Sans — для основного текста и фраз.
- Блок «Моменты» скрывается полностью, если публичных фотографий нет. При одной фотографии показывается увеличенный полароид; при двух — две сбалансированные карточки; при трёх — один основной и две дополнительные карточки.
- Подписи полароидов занимают общую нижнюю безопасную область, ограничены двумя-тремя строками и при необходимости сокращаются по границе слова.
- В Post подпись второй фотографии, а в Print подписи дополнительных фотографий используют компактную нижнюю безопасную область: текст располагается ниже окна фотографии и не пересекает изображение.
- Карточки фраз имеют отдельные зоны: кавычка сверху слева, текст в центре, сердце снизу справа. Контент не должен пересекать рваные края.
- Story строится в фиксированном холсте 1080 × 1920. Завершающая бумажная секция, логотип и слоган должны оставаться видимыми; снизу сохраняется безопасная зона.
- Print формируется как один полноцветный лист A4 portrait с безопасными полями; PDF содержит растеризованный финальный макет без приватных URL или данных.
- В рендере `ImageResponse` не передаются CSS-свойства со значением `undefined`: это гарантирует скачивание и для бумажного шаблона, где декоративные рамки не используются.
- `ImageResponse` не декодирует WebP/AVIF-ассеты профиля напрямую. Общий universal export resolver перед растеризацией отдаёт такие локальные ассеты через защищённый PNG-маршрут; профиль при этом продолжает использовать оптимизированный WebP/AVIF в Web. Новый шаблон не должен хранить отдельные ручные PNG-копии только ради Story/Post/A4.
- Экспортные section-underlay с nine-slice/horizontal-slice сначала собираются сервером в один PNG нужного размера, а затем добавляются в секцию обычным растровым слоем. Нельзя оставлять их вложенными абсолютными слоями: `ImageResponse` может потерять подложку или создать чёрный прямоугольник размером с прозрачную секцию.
- Художественная бумага под заголовком блока или подписью фотографии, обязательная для смысла композиции, задаётся профильным растровым ассетом. Нельзя полагаться только на `background`, `clip-path`, CSS-градиент или тень: Satori может отрисовать текст без подложки.
- При приёмке растровой подложки проверяется не только CSS-контейнер, но и видимая область внутри файла. Бумага должна занимать почти весь прозрачный холст, а внутренние отступы контейнера обязаны вмещать максимальный разрешённый текст во всех форматах Story/Post/A4.

## Шаблон «Маршрут»

Экспорт для «Маршрута» определяется по `card.templateId` и рендерится отдельным макетом. Бумажный шаблон продолжает использовать свой экспортный макет и свои ассеты: изменения «Маршрута» не должны влиять на него.

На публичной странице `/share/{token}` завершающий блок «В полной открытке — ещё больше тепла» для «Маршрута» должен быть размещён на бумажном листе:

- ассет: `/templates/route-adventure/closing-kraft-note.png`;
- текст — тёмный, с достаточным контрастом;
- это правило относится именно к публичной странице, а не только к скачиваемым файлам.

Для экспортов используются ассеты «Маршрута», уже применяемые в публичной открытке:

| Блок | Ассет / правило |
| --- | --- |
| Хедер | `hero-expedition.png`. В post и PDF сохранять пропорции фона (`cover`), чтобы компас не растягивался. |
| Качества | `leather-stitch-panel.png`. |
| «Моменты» | `moments-field-panel.png`; заголовок и подзаголовок находятся над второй и третьей фотографиями. |
| Полароиды | `polaroid-narrow-cream.png` и `polaroid-narrow-cream-overlay.png`. Фото заполняет окно рамки без чёрных полос; подпись располагается в нижней зоне рамки. |
| Тёплые слова | `quotes-gunmetal.png`, а не простая заливка и не бумажная карточка. |
| Подвал экспорта | `closing-kraft-note.png`. |

Подложка каждого блока должна занимать весь выделенный блок без повторов, обрывов или незакрытых участков фона. Хедер настраивается отдельно: его не следует менять при исправлении подложек остальных секций.

Для story качества отображаются сеткой 2–1–2, а две цитаты располагаются в один ряд. В post и print показываются три карточки цитат в один ряд.

Для трёх фотографий в «Маршруте» заголовок «Моменты» размещается в свободной области слева, а не добавляет отдельную строку к высоте блока. В Story основной полароид выравнивается по нижнему краю с двумя дополнительными; в Print фотографии поднимаются выше нижнего шва ассета. Это сохраняет место для завершающей бумажной секции с логотипом и слоганом.

Внешние поля экспортов «Маршрута» используют нейтральный тёмный фон с деликатной текстурой: фон не должен образовывать заметную зелёную полосу вдоль левого края.

## Проверка перед выпуском

1. Открыть диалог и убедиться, что до нажатия «Скачать» не отправлен ни один `/image/{format}` запрос.
2. Скачать Story и проверить полную видимость подвала, отсутствие обрезания снизу и выравнивание нижних краёв полароидов.
3. Скачать Post и проверить естественные интервалы и равную высоту карточек фраз.
4. Открыть скачанный PDF при 100% масштабе: одна страница A4, читаемые подписи, фразы, логотип и слоган; фотографии не пересекают нижний шов блока «Моменты».
5. Проверить варианты с 0–3 фотографиями, 0–5 качествами, длинными именами, длинными подписями и скрытыми счётчиками.
6. Проверить HTTP-ответы всех четырёх маршрутов на реальном публичном токене: Story/Post/Print preview — `200 image/png`, Print — `200 application/pdf`.
7. Во время Story многократно запросить `/` и `/?_rsc=test`: ответы должны оставаться `200` без timeout.
8. Проверить `export:*` до `export:complete`, отсутствие `EAI_AGAIN`, `Connection terminated unexpectedly`, dynamic font и `z-index` warnings.
9. Смоделировать серверную ошибку или `429`: сообщение должно быть понятно пользователю, а кнопка должна вернуться в состояние «Скачать».

## Экспорты ателье `universal-v1`

Общий renderer новых оформлений повторяет смысловую структуру обновлённых скачиваемых файлов «Маршрута», но сохраняет профильные ассеты, цвета, шрифты и фоторамки конкретного шаблона.

Ателье является источником истины для экспортной композиции. Его Story/Post/A4 и продуктовые маршруты скачивания используют один `UniversalTemplateExportCard` и один `resolveTemplateExportAsset`. Все профильные `crop`, `width`, `height`, `nine-slice` и `horizontal-slice` проходят через `/api/template-export-asset`; сырой `/templates/...` URL с параметрами преобразования не считается отрисованным ассетом. Отдельная геометрия конкретного шаблона в route скачивания запрещена.

Для каждого нового профиля обязательна интеграционная проверка, что page underlay и closing underlay в ателье разрешаются через `/api/template-export-asset` во всех трёх форматах. Так следующая открытка наследует уже проверенную обработку ассетов и не требует повторного ручного выравнивания после регистрации в продукте.

Каждый слой декора, видимый в экспорте, обязан иметь независимые `exportVariants` для Story, Post и A4. Экспортная секция разрешает таким слоям выходить за свои границы — в частности, hero-декор может продолжаться в свободную область качеств. Обрезание выполняется только по внешнему холсту готового файла. Общие Web/mobile-координаты не используются как скрытая экспортная настройка и не должны меняться ради исправления одного скачиваемого формата.

Счётчики поздравлений и фотографий используют профильный preset и палитры как единый визуальный контракт для самой открытки и всех экспортов. Если подвал содержит предметные группы по краям и спокойную бумагу в центре, применяется `horizontal-slice`: защищённые края масштабируются пропорционально, а расширяется только центральная область без значимого декора.

- Пять качеств во всех форматах располагаются сеткой `2–1–2`; средняя карточка центрируется, а пары первой и третьей строк разделены интервалом шириной в одну карточку.
- Story и A4 показывают три фотографии: слева крупная карточка, над ней заголовок «Моменты» и описание; справа две меньшие карточки столбцом.
- Post показывает первые две фотографии: крупную слева и меньшую справа; заголовок и описание находятся над правой карточкой.
- Все полароиды слегка повёрнуты разными углами как единые контейнеры, поэтому рамка, фотография, overlay и подпись не расходятся.
- Если подпись фотографии оформлена отдельным бумажным листом, профиль задаёт `photoFrames.*.caption.exportUnderlay`; если бумага нужна заголовку «Моменты», используется `export.memoriesHeadingUnderlay`. Оба ассета проходят через общий export resolver и не дублируются в route конкретного шаблона.
- Story/Post/A4 показывают соответственно 2/3/3 карточки в блоке «Особенно тёплые слова»; в пределах одного формата все цитаты используют одинаковый кегль.
- Подложки качеств и цитат сохраняют углы и художественные края через девятисегментную отрисовку; допускается растяжение только спокойных центральных зон без значимого рисунка.
- Завершающий блок использует единый текст приватности, логотип и слоган Slovesto; боковой рисунок подложки масштабируется пропорционально по полной высоте, а по горизонтали расширяется только центральная зона.

## Шаблон «Бумажный»

Экспорт «Бумажного» шаблона использует те же визуальные ассеты, что и публичная открытка: бумажные слои, цветные теги качеств, карточки цитат, полароидные рамки, наклейки и камеру. В серверном рендере ассеты должны добавляться явными тегами `<img>`, а не только CSS-свойством `background`: так прозрачные PNG стабильно попадают в Story, Post и Print.

Счётчик фотографий для «Бумажного» экспорта считается по медиа, реально вошедшим в финальную композицию. Это совпадает с публичной открыткой и не учитывает загруженные, но не отображаемые медиа. Логика счётчика «Маршрута» сохранена без изменений.

Post намеренно содержит до двух фотографий; Story и Print — до трёх. Перед выпуском проверять все три формата на карточке с тремя фотографиями и тремя цитатами.

Фото в полароидах «Бумажного» шаблона располагаются строго по прозрачным окнам исходных PNG-рамок: с `object-fit: cover`, без выхода под бумажную рамку и без незаполненных полос. Это правило применяется только к бумажной ветке экспортного рендера; геометрия полароидов «Маршрута» независима.

В Story с тремя фотографиями заголовок «Моменты» и подзаголовок должны находиться на бумажной подложке. Две малые карточки справа сближаются симметричным сдвигом: верхняя вниз, нижняя вверх; их подписи располагаются чуть выше стандартной нижней позиции.

В Print большой полароид в «Моментах» выравнивается по бумажной подложке и не выходит за её левый край; малые карточки справа сближаются тем же симметричным сдвигом. Ряд трёх карточек цитат расширяется в пределах безопасных полей A4 и использует уменьшенный промежуток, чтобы длинная третья фраза не обрезалась.

Декоративная кавычка на карточках цитат располагается выше и левее начала текста и не пересекается с ним. Полароиды Print используют ту же надёжную схему слоёв, что и Story: фото лежит под исходной PNG-рамкой, оба слоя находятся в одном повёрнутом контейнере, а внешнего `scaleX` у бумажных карточек нет. Положение большого Print-полароида задаётся через `left`/`top`, а не дополнительным `transform` вокруг уже повёрнутой карточки: это исключает раздельную растеризацию фото и рамки. Поэтому рамка перекрывает край снимка, и отдельные компенсационные сдвиги или повороты фото не требуются.

Для «Маршрута» заголовок блока «Моменты» в Story поднят над большим полароидом. В Print горизонтальное масштабирование полароидов объединено с их поворотом в одном контейнере, а позиция задаётся через `left`/`top`; фото, рамка и оверлей поэтому не расходятся при растеризации. Большой полароид имеет безопасный отступ от левой границы панели с учётом поворота и не обрезается. В Story и Print подложка заключительного блока немного растягивается по вертикали, чтобы строка слогана оставалась внутри листа.

В Post нельзя передавать `transform: undefined` в стили `ImageResponse`: для шаблонов без сдвига свойство полностью исключается из объекта стилей. Это сохраняет бумажный сдвиг и позволяет «Маршруту» стабильно формировать PNG.
