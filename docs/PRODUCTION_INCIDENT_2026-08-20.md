# Production incident: перегрузка VPS и отказ публичного экспорта

Дата: 20 августа 2026 года.

Статус: устранено.

## Краткое резюме

Публичные экспорты Story/Post/A4 зависали или завершались по timeout, `/example` загружался 10–15 секунд, manager отвечал нестабильно. `capsule-web` оставался healthy, но периодически не мог ответить даже внутри Docker network.

Первоначальный export-код действительно имел собственные проблемы: диалог запускал несколько форматов сразу, а Satori/Resvg блокировал основной Node.js process. После исправления этих проблем production всё равно оставался медленным.

Окончательная причина — скомпрометированный контейнер соседнего проекта `predictions-prod-frontend-1`, который занимал почти все ресурсы двухъядерного VPS.

## Влияние

- `/example` не завершал навигацию в Chrome за 10 секунд.
- Story не доходил дальше `export:start`.
- Через 82 секунды proxy завершал запрос с timeout.
- В логах появлялись `getaddrinfo EAI_AGAIN postgres` и пустые image responses.
- Обычные RSC/image-запросы могли получать 502 через Caddy.
- Клиент показывал ошибку скачивания вместо файла.

Данные Slovesto и PostgreSQL не были повреждены.

## Временная линия

| Дата | Событие |
| --- | --- |
| 11 июня | Создан production image frontend проекта «Прогнозист». |
| 11 августа | Контейнер `predictions-prod-frontend-1` запущен повторно. |
| 16 августа | В writable layer контейнера появился/изменился `/bin/.rguard`. |
| 19 августа | Добавлена демонстрационная открытка Кими `school-scrapbook` на `/example` и главную. |
| 20 августа | Исправлен export pipeline Slovesto и добавлен изолированный worker. |
| 20 августа | Найдена общая перегрузка VPS и скомпрометированный контейнер. |
| 20 августа | Все ресурсы «Прогнозиста» удалены, Caddy перенесён в Compose Slovesto. |

Заражение предшествовало демонстрационному деплою Кими. Деплой Кими не был источником вредоносного процесса.

## Технические признаки

До очистки:

- VPS: 2 CPU;
- load average: 17–28;
- CPU idle: `0%`;
- system CPU: 77–82%;
- доступная RAM в одном из замеров: около 156 МБ;
- `predictions-prod-frontend-1`: до 177,5% CPU, 403 процесса;
- `.rguard`: 12 активных процессов;
- zombie-процессы: 359;
- свободное место: 4,4 ГБ, диск заполнен на 85%.

Файл `/bin/.rguard` запускался от root внутри контейнера, каждые 0,1 секунды обходил `/proc`, завершал конкурирующие процессы и удалял файлы с именами `xmrig` и других майнеров. Контейнер не был privileged, не использовал host PID и не имел host mounts, однако источник проникновения не установлен.

## Почему проблема проявилась после Кими

Совпали два фактора:

1. Заражённый контейнер уже отнимал CPU и создавал системную нагрузку.
2. Новый `school-scrapbook` тяжелее старых демонстраций: больше декора и фотографий, полный универсальный renderer и высокое разрешение экспортов.

Лёгкие запросы раньше ещё помещались в оставшийся ресурс. Новая демонстрация и Story пересекли критический порог, поэтому по времени проблема выглядела следствием деплоя Кими. Фактически новый шаблон лишь сделал существующую деградацию заметной.

Дополнительным усилителем был старый диалог скачивания: при открытии он создавал реальные preview для всех трёх форматов. Это исправлено отдельно.

## Исправления в Slovesto

- Диалог не запускает export-запросы до выбора формата.
- Выполняется только выбранный Story/Post/A4.
- Satori/Resvg вынесен в отдельный Next.js process на `127.0.0.1:3001`.
- Worker имеет `nice -n 10`, concurrency `1`, timeout и принудительный restart.
- Шрифты загружаются локально.
- Преобразованные export-assets используют ограниченный cache.
- Клиент всегда снимает состояние «Подготовка файла» через `finally`.
- Добавлены этапные логи `export:*` с `durationMs`.

Коммиты:

- `85907a3` — исправление публичного диалога и export pipeline;
- `d9ba29b` — изоляция renderer;
- `d3df2f6` — пониженный CPU priority worker;
- `7e4819f` — собственный Caddy внутри `capsule`.

## Выполненная очистка VPS

Без возможности восстановления удалены:

- пять контейнеров `predictions-prod-*`;
- старый контейнер `predictions_bot`;
- production и dev Docker networks проекта;
- обе PostgreSQL-базы «Прогнозиста»;
- Caddy volumes старого проекта;
- шесть старых anonymous `node_modules` volumes;
- все пользовательские images `predictions-*`;
- `/home/deploy/prognozist`, включая исходники, backups и env-файлы;
- 8,08 ГБ неиспользуемого Docker build cache.

При остановке обнаружилась скрытая зависимость: Caddy «Прогнозиста» одновременно обслуживал `slovesto.ru`. Публичный HTTPS кратковременно стал недоступен, хотя web и PostgreSQL Slovesto оставались healthy. Для устранения зависимости создан `capsule-caddy-1` с собственными volumes и `infra/Caddyfile`.

## Незавершённые меры безопасности

Источник проникновения в старый контейнер не установлен. Несмотря на отсутствие privileged mode и mounts, рекомендуется отдельно:

1. Ротировать SSH credentials VPS.
2. Проверить authorized keys и системных пользователей.
3. Ротировать любые секреты, которые могли повторно использоваться в двух проектах.
4. Обновить ОС и Docker после отдельного backup/maintenance window.
5. Периодически проверять `docker ps -a`, `docker stats`, `vmstat` и число процессов.

Эти меры не выполнялись в рамках очистки, потому что требуют отдельного управления доступами и окна обслуживания.
