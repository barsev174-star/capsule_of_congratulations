## Цель дизайна

За первые несколько мобильных экранов человек должен понять последовательность:

`ученики и родители пишут каждый своё → организатор собирает материалы → получается одна оформленная открытка → учитель открывает готовый подарок`.

Главное доказательство — настоящий `school-scrapbook`. Не показывай в hero редактор, dashboard или административный интерфейс.

Страница должна ощущаться частью Slovesto, но быть чище и собраннее текущей главной. Это не школьный сайт и не тематическая доска с мелками: школьная художественная палитра живёт только внутри изображения готовой открытки.

## Визуальное направление

### Интерфейсная палитра

Используй правила `AGENTS.md`:

```css
--ui-bg: #ffffff;
--ui-bg-subtle: #f7f8fa;
--ui-text: #202124;
--ui-text-secondary: #5f6368;
--ui-text-muted: #8a9099;
--ui-accent: #e9652f;
--ui-accent-hover: #df5f2e;
--ui-accent-active: #c7532a;
```

- основной CTA — сплошной оранжевый;
- вторичный CTA — белый/нейтральный с оранжевым текстом или рамкой;
- не использовать коричневый, кофейный, сепию и терракоту в тексте, контролах, границах, иконках и тенях;
- тени строить на чистом чёрном с низкой прозрачностью;
- синие, жёлтые и другие школьные цвета не переносить из открытки на интерфейсные кнопки, badges и navigation.

Существующие legacy brown-токены главной не являются разрешением использовать их на новой странице. При конфликте приоритет имеет `AGENTS.md`.

### Типографика

- использовать уже подключённые шрифты проекта;
- H1/H2/H3: `text-wrap: balance`;
- короткие описания и карточки: `text-wrap: pretty`;
- не уменьшать основной текст ниже комфортного мобильного размера;
- H1 на 320–390 px не должен занимать почти весь первый экран;
- не вводить новый декоративный шрифт;
- не имитировать школьный почерк в интерфейсных текстах.

### Поверхности

- основа страницы белая или `#f7f8fa`;
- чередовать секции преимущественно расстоянием и нейтральной поверхностью, а не цветными полосами;
- карточки использовать только там, где они помогают сравнению или группировке;
- для глубины карточек предпочитать многослойную нейтральную тень сплошной цветной рамке;
- реальные divider и input/focus boundaries могут оставаться границами;
- близко вложенные поверхности должны иметь концентрические радиусы: внешний радиус = внутренний радиус + padding;
- изображения получают внутренний `outline: 1px solid rgba(0, 0, 0, 0.1)`.

## Структура и задача каждого блока

Тексты и порядок берутся из технического плана. Не переписывай смысл и не добавляй новые продуктовые обещания.

### Hero

На desktop — две колонки: copy слева, фрагмент готовой школьной открытки справа. На mobile — copy, CTA и доказательства должны появиться до крупного визуала либо визуал должен занимать компактную предсказуемую высоту.

Требования:

- H1, основной текст, два CTA и строка условий видны без длинной прокрутки;
- основной CTA доминирует;
- вторичный CTA не конкурирует с основным;
- сезонная плашка встроена спокойно и не выглядит рекламным badge;
- visual показывает именно результат `school-scrapbook`;
- не собирать hero из множества мелких декоративных объектов;
- изображение не должно создавать CLS.

### «Слова каждого»

Три голоса — ученик, родитель, выпускник. Они должны восприниматься как три разных человека, но не как чат и не как отзывы клиентов.

Не использовать speech bubbles мессенджера. Предпочтительны короткие бумажные/карточные фрагменты в нейтральном UI с небольшими ролевыми метками.

### Четыре шага

На desktop — читаемая последовательность; на mobile — вертикальная схема без горизонтального скролла.

Визуальная связь должна поддерживать цепочку:

`организатор → ссылка → класс → открытка → учитель`.

Не перегружать шаг 4 перечнем всех действий: детали остаются в тексте, иллюстрация показывает результат.

### Центральный результат

Блок «Поздравления не остаются списком сообщений» является главным конкурентным объяснением страницы.

Нужно показать, что в одном результате соединяются:

- фотографии;
- личные поздравления;
- качества;
- лучшие фразы;
- общее оформление;
- контроль организатора.

Не изображать автоматическую магию: роль организатора должна оставаться видимой.

### Школьный example

Это визуально самый сильный блок после hero.

- крупный preview `school-scrapbook`;
- понятная кнопка открытия интерактивного примера;
- второй CTA создания;
- preview выглядит кликабельным, но не маскирует ссылку под неочевидную область;
- кнопка запуска с play-icon выровнена оптически, треугольник можно сдвинуть на 2 px вправо;
- не встраивать renderer и не имитировать внутри landing работу полной открытки.

### Участники и фотографии

Собрать в один компактный responsive-блок:

- ученики;
- родители;
- весь класс;
- фотографии выбирает организатор.

Не делать отдельную тяжёлую gallery. Использовать существующий preview или небольшие оптимизированные фрагменты, если они уже есть в проекте.

### Поводы

Поводы — не ссылки и не фильтры. Не оформлять их как элементы управления. Возможны нейтральные chips или компактная сетка, но без ложного affordance.

### Цена

Иерархия:

1. сначала можно собрать и проверить;
2. `399 ₽ один раз`;
3. оплата только перед вручением;
4. без подписки.

Не использовать зачёркнутые цены, скидки, псевдотарифы и расчёт «с человека».

### FAQ и финальный CTA

FAQ должен оставаться компактным на mobile. Кнопка вопроса целиком кликабельна, focus заметен, открытие/закрытие interruptible.

Финальный CTA — ясное завершение страницы, без новой визуальной идеи, которая конкурирует с hero.

## Responsive

Обязательная проверка:

- 320×568;
- 360×800;
- 390×844;
- 430×932;
- 768×1024;
- 1280×720;
- 1440×900;
- 1920×1080.

На mobile:

- нет горизонтального overflow;
- H1 не занимает чрезмерное число строк;
- CTA имеет ширину и высоту, удобные для нажатия;
- карточки идут вертикально;
- четыре шага читаются без масштабирования;
- example заметен при обычном скролле;
- цена и условие оплаты не разнесены далеко друг от друга;
- длинные FAQ-вопросы не сталкиваются с chevron;
- footer не ломается на 320 px.

## Интерактивные состояния и motion

- interactive hit area — минимум 40×40 px, предпочтительно 44×44 px;
- primary и secondary CTA: `active` использует `scale(0.96)`;
- transitions задаются только для реально меняющихся свойств;
- `transition: all` запрещён;
- `will-change: all` запрещён; любой `will-change` добавляется только после обнаруженного stutter;
- hover-стили применять внутри `@media (hover: hover) and (pointer: fine)`;
- focus-visible заметен и не зависит только от смены цвета;
- поддержать `prefers-reduced-motion`;
- не добавлять motion/framer-motion или другую зависимость;
- не устраивать обязательную entrance-анимацию всему hero;
- если используются reveal-анимации ниже fold, контент не должен оставаться скрытым при ошибке JS;
- FAQ открывается через interruptible CSS transition, а не фиксированный keyframe timeline.

## Критерии приёмки

| До / риск | После / требуемый результат |
| --- | --- |
| Hero выглядит как абстрактный сервис открыток | С первого экрана ясно: это открытка учителю от учеников и родителей |
| Главный визуал похож на редактор | Показан фрагмент готового `school-scrapbook` |
| Школьная палитра окрашивает controls | Художественные цвета остаются только внутри открытки; UI нейтральный с оранжевым CTA |
| Длинная цепочка отдельных похожих секций | Десять блоков с ясной сменой аргумента и компактным мобильным ритмом |
| Карточки имеют одинаковые вложенные радиусы | Близкие вложения используют концентрические радиусы |
| Цветные border создают глубину | Карточки используют нейтральные многослойные тени; divider остаются границами |
| Изображения сливаются с поверхностью | Внутренний outline `rgba(0, 0, 0, 0.1)` без влияния на layout |
| CTA реагирует резко или чрезмерно | Interruptible transition и `scale(0.96)` на active |
| Маленькие icon-actions | Hit area минимум 40×40 px без перекрытия соседних controls |
| Все свойства анимируются | Переходы перечисляют только `background-color`, `color`, `box-shadow`, `opacity`, `transform` по необходимости |
| Заголовки получают случайные переносы | Заголовки используют `text-wrap: balance`, короткие тексты — `pretty` |
| Mobile является уменьшенным desktop | На 320–430 px самостоятельная вертикальная композиция без overflow и длинного первого экрана |
