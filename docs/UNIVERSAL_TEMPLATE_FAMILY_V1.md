# Универсальная семья шаблонов `universal-v1`

Статус: утверждённый контракт этапа 1.

Дата: 11 августа 2026 года.

Связанные документы:

- `TEMPLATE_AUTOMATION_IMPLEMENTATION_PLAN_2026-08-11.md`;
- `TEMPLATE_CREATION_RUNBOOK.md` — рабочая инструкция, asset- и acceptance-чек-листы;
- `LEGACY_TEMPLATE_BASELINE_2026-08-11.md`;
- задача `P2-13` в сводном списке замечаний.

## 1. Граница семьи

`universal-v1` — не произвольный конструктор страниц. Все шаблоны этой семьи используют одинаковые семантические блоки, правила контента, адаптивные состояния и экспортные композиции. Между оформлениями меняются художественные ассеты, разрешённые цвета, шрифты и ограниченные токены геометрии.

В профиле запрещены:

- произвольные React-компоненты;
- HTML-фрагменты;
- CSS-строки и селекторы;
- исполняемые callbacks;
- отдельные ветки по `templateId` в private, public и export-renderer.

Если новое оформление не помещается в этот контракт, для него проектируется новая структурная семья.

Визуальные примеры текущих механик находятся в `screenshots/template-legacy-baseline/`: восемь web-состояний и Story/Post/Print для Paper и Route. Канонический эталон блока «Моменты» — Route: на desktop и экспортных форматах три фото идут горизонтальной лентой, при ширине до `640px` — вертикально. Схема с крупным фото слева и двумя меньшими справа признана ошибочной и не используется.

## 3. Канонический порядок и доступность блоков

| Блок | Private | Public | Story/Post/A4 | Обязательность |
|---|---|---|---|---|
| `hero` | Да | Да | Да | Обязательный |
| `summary` | Да | Нет | Нет | Обязательный private-блок |
| `qualities` | Да | При разрешении | Да | Необязательный |
| `messages` | Да | Нет | Нет | Обязательный private-блок |
| `memories` | При ровно 3 фото | При ровно 3 разрешённых фото | При ровно 3 разрешённых фото | Необязательный |
| `quotes` | 2–3 из рекомендаций организатора | 2–3 из выбранных получателем | 2 для Story/Post, 3 для A4 | Необязательный |
| `closing` | Да | Нет | Нет | Обязательный private-блок |
| `public-note` | Нет | Да | Да | Системный, не настраивается профилем |

Рекомендуется не переносить пользовательский `finalBlockOrder` в `universal-v1`. Поле остаётся рабочим для legacy-шаблонов, но новая семья использует канонический порядок. Это исключает расхождение web/export и не превращает профиль в конструктор страниц.

## 4. Шесть схем поздравлений

| ID сценария | Композиция | Поздравлений в основном состоянии | Бюджет одного текста | Фото |
|---|---|---:|---:|---:|
| `grid-2` | Сетка 2 × 2 | 4 | 280 символов | 0 |
| `carousel-1` | Один ряд | 3 | 340 символов | 0 |
| `carousel-2` | Два ряда по 3 | 6 | 200 символов | 0 |
| `portrait` | Колонка поздравлений + вертикальное фото | 3 | 280 символов | 1 |
| `landscape-pair` | Колонка поздравлений + два горизонтальных фото | 4 | 280 символов | 2 |
| `landscape-trio` | Прокручиваемая колонка поздравлений + три горизонтальных фото, распределённых по высоте и смещённых по горизонтали | 4 | 280 символов | 3 |

Для `carousel-2` предлагается зафиксировать фактический лимит renderer — 200 символов — и исправить подпись редактора на этапе внедрения новой семьи. Legacy-поведение и сохранённые открытки при этом не меняются.

На desktop все поздравления пролистываются прямо внутри ограниченной по высоте колонки. Для одного вертикального фото одновременно видны три карточки, для двух или трёх горизонтальных фото — четыре. Пара центрируется по высоте как единая группа; три фото распределяются по высоте и имеют Route-смещения по горизонтали. Отдельной кнопки «Все поздравления» под блоком нет. Счётчик с подписью `12 поздравлений` открывает диалог со всей подборкой.

Эти правила не копируются в каждый новый шаблон. Они входят в структурный preset `route-v1` из `src/lib/templates/layout-presets.ts`; `TemplateProfile` выбирает preset, а художественный профиль задаёт только ассеты, цвета, типографику и нормализованную геометрию рамок. Количество выбранных фото автоматически определяет media-сценарий, поэтому несовместимые комбинации вроде одного фото со схемой trio не допускаются.

## 5. Контентные лимиты

| Поле | Лимит | Поведение при переполнении |
|---|---:|---|
| Имя получателя | 46 символов | До двух строк и ступенчатое уменьшение шрифта; затем ошибка профиля/fixture |
| Повод | 60 символов | Одна-две строки; затем многоточие |
| Дата события | ISO `YYYY-MM-DD` в данных | Формат вывода `dd MMMM yyyy` с русским месяцем в родительном падеже; под поводом; пустое значение не создаёт строку или отступ |
| Hero description | Системный текст | Не задаётся шаблоном |
| Главное о тебе | 500 символов | Жёсткий лимит; абзацы, без прокрутки и без многоточия; после текста выводится автор |
| Поздравление участника | 200/280/340 по схеме | Обрезка только в карточке; полный текст доступен в диалоге |
| Качество | 28 символов | До двух строк; далее отклонение fixture/profile |
| Лучшая фраза | 100 символов | До трёх строк; далее отклонение |
| Заголовок «Моментов» | 80 символов | До двух строк; далее отклонение |
| Описание «Моментов» | 180 символов | До трёх строк; далее многоточие |
| Подпись фото | 45 символов | Полный вывод без многоточия; до двух строк и shrink-to-fit в пределах утверждённого минимального кегля; рамка, не вмещающая тестовую подпись из 45 символов, не проходит валидацию |
| Private signature | 180 символов | До трёх строк; далее многоточие |

Лимиты считаются частью семейного контракта и одинаково валидируются для web, public и export до рендера.

## 6. Контракт фоторамки и кадрирования

```ts
type NormalizedRect = {
  x: number;      // 0…1
  y: number;      // 0…1
  width: number;  // 0…1
  height: number; // 0…1
};

type UniversalPhotoFrame = {
  aspectRatio: number;
  base?: AssetRef;
  aperture: NormalizedRect;
  overlay?: AssetRef;
  captionArea: NormalizedRect;
  fit: "cover";
  caption: {
    maxChars: 45;
    maxLines: 2;
    align: "left" | "center" | "right";
    fontToken: "body" | "handwritten";
    minScale: number;
  };
};

type UniversalPhotoCrop = {
  x: number;    // 0…1
  y: number;    // 0…1
  zoom: number; // 1…разрешённый максимум
};
```

Один и тот же `UniversalPhotoCrop` передаётся в private, public и export. Преобразование текущих процентов `0…100` выполняется в одном legacy-адаптере и не дублируется по поверхностям.

Для `memories` профиль не задаёт произвольное количество карточек. Каноническое состояние содержит ровно три фото:

- mobile web до `640px`: три полноширинные карточки в одном столбце;
- desktop web, Story, Post и A4: три карточки идут одним горизонтальным рядом, первая может быть немного шире; заголовок и описание расположены над рядом;
- Story/Post: сохраняются все три фото и их порядок, но размеры коллажа адаптируются под safe area формата.

Если в private или public разрешено не ровно три фото, блок целиком не рендерится. Интерфейс выбора для новой семьи предлагает состояния «не публиковать» или «выбрано 3 из 3», без промежуточной композиции для одного или двух фото.

## 7. Дата события и публичная видимость

Источник даты — `card.eventDate`, уже редактируемый в «Основе открытки → Дополнительные настройки». В семантической модели Hero дата остаётся ISO-строкой, а форматируется общим formatter непосредственно перед рендером.

Правила одинаковы для private, public и export:

- дата располагается сразу под поводом и до имени получателя;
- формат: `01 января 2026`;
- при `null` или пустом значении дата и её вертикальный отступ отсутствуют;
- public-настройка получает независимый флаг `showEventDate`, расположенный рядом с `showOccasion`, `showGreetingCount` и `showPhotoCount`;
- при наличии даты переключатель по умолчанию включён; если даты нет, переключатель не показывается;
- Story/Post/A4 используют тот же `showEventDate`, поэтому preview и скачиваемый файл совпадают с публичной страницей.

## 8. Поток «Лучших фраз»

1. Анализ поздравлений создаёт от 3 до 6 уникальных кандидатов, каждый не длиннее 100 символов.
2. Организатор отмечает ровно 3 рекомендации. Остальные кандидаты не удаляются.
3. Получатель при настройке публичной версии видит весь набор из 3–6 кандидатов, рекомендации организатора отмечены, и выбирает ровно 3 фразы в нужном порядке.
4. Private-открытка использует рекомендации организатора, public и публичные exports — выбор получателя.
5. Web и A4 показывают 3 фразы; Story/Post показывают первые 2 из выбранной тройки. Ни одна поверхность не показывает невыбранного кандидата.

## 9. Разрешённые слои и токены профиля

Профиль может задавать:

- `SectionSurface`: один фон или готовая поверхность блока;
- `ComponentFrame`: необязательный base, окно контента, необязательный overlay;
- `AnchoredImage`: декоративное изображение, привязанное к семантическому anchor;
- цвета `page`, `text`, `muted`, `accent`, `surface`;
- шрифты `heading`, `body`, `handwritten` из разрешённого реестра;
- ограниченные размеры, padding, opacity, rotation и breakpoint overrides;
- видимость декора на desktop/mobile/export.

Все координаты и размеры хранятся в нормализованном виде либо как токены заранее определённой шкалы. Свободные CSS-единицы и селекторы не допускаются.

## 10. Поверхности экспорта

| Формат | Размер v1 | Фото | Фразы | Особенность |
|---|---:|---:|---:|---|
| Story | `1080 × 1920` | Ровно 3 либо блок скрыт | 2 | Вертикальная адаптация коллажа |
| Post | `1080 × 1350` | Ровно 3 либо блок скрыт | 2 | Плотная адаптация коллажа |

Web и export используют одни семантические данные, asset refs, рамки, crop и safe areas, но разные технические компоненты. Preview и скачиваемый файл обязаны строиться одним export-renderer.

## 11. `TemplateProfile`

Типы, runtime-валидация и `defineTemplate` реализованы в `src/lib/templates/profile.ts`. Реестр и диспетчер находятся в `src/lib/templates/registry.ts` и `src/lib/templates/dispatcher.ts`. Ниже сохранена сокращённая форма профиля для чтения документа; фактический тип дополнительно фиксирует нормализованные фоторамки, разрешённые декоративные слои, локальные asset refs и бюджеты в байтах.

Asset-контракт художественной кожи не допускает одной произвольной картинки, растянутой на все поверхности:

- `hero`, `summary`, `qualities`, `messages`, `memories`, `quotes` и `closing` получают семь независимых подложек, каждая с общим preset-ом растяжения и собственной safe-area;
- `greetingCards` содержит либо пустой список, либо ровно четыре подложки; renderer назначает их карточкам по кругу `1 → 2 → 3 → 4 → 1` и сохраняет тот же порядок в диалоге всех поздравлений;
- portrait- и landscape-фоторамки состоят из `base`, нормализованного `aperture`, фотографии с сохранённым crop, `overlay` и `captionArea`; новые оформления выбирают общий preset и не двигают окно рамки попиксельно;
- индивидуальные координаты текста для отдельных художественных файлов запрещены: текст остаётся в семантической safe-area и адаптируется только в пределах утверждённых content-пресетов.

```ts
defineTemplate({
  id: "new-template",
  family: "universal-v1",
  layoutPreset: "route-v1",
  metadata: { name, description, accent, preview },
  assets: {
    page,
    hero,
    summary,
    qualities,
    greetingCards,
    messagePhotoFrames,
    memories,
    memoryPhotoFrames,
    quotes,
    closing,
    decor
  },
  typography: { heading, body, handwritten },
  colors: { page, text, muted, accent, surfaces },
  intro: { surface, text, accent, mark, pattern },
  public: { blocks: ["hero", "qualities", "memories", "quotes"] },
  export: { profile: "universal-export-v1" },
  performance: { networkBudget, decodedMemoryBudget },
  demo: { fixture: "full-card-default" }
});
```

## 12. Завершение этапа 1

Контракт утверждён пользователем 11 августа 2026 года с уточнениями по дате события, полному выводу подписей и главного поздравления, потоку лучших фраз и единственной трёхфотографической схеме «Моментов».

Критерий перехода к этапу 2 выполнен. Следующая реализация начинается с типов и валидации `TemplateProfile`, канонической модели Hero с `eventDate`, публичного флага `showEventDate` и тестовых fixture на граничные значения 45/100/500 символов и ровно три фото.
