# Анимация вручения «Собрать поздравления»

Дата: 2026-08-31.

## Назначение

`collect-messages` — вторая вступительная анимация публичной открытки. Она существует рядом с текущим сценарием `envelope`, не заменяет его и выбирается организатором для конкретной открытки. До запуска получатель видит самостоятельную idle-сцену с чатами, короткими превью поздравлений, фотографиями под соответствующими сообщениями и CTA «Собрать поздравления».

После нажатия сцена последовательно показывает, как выбранные материалы отделяются от фонового общения, собираются во временную колонку, а затем переходят в шаблон открытки. По завершении интро открывается обычная финальная открытка; содержимое и порядок блоков финальной страницы не меняются.

## Продуктовый контракт

- Доступны два значения `GiftAnimationId`: `envelope` и `collect-messages`.
- Значение по умолчанию для существующих и новых записей — `envelope`.
- Организатор выбирает вариант в `/manage`; выбранное значение сохраняется вместе с открыткой.
- `/example` позволяет запустить оба варианта на демонстрационных данных.
- Публичный `/gift/{finalSlug}` получает выбранный вариант и подготовленное сервером безопасное превью.
- Кнопка «Пропустить» остаётся доступной во время вступительной сцены.

## Данные превью

В анимацию передаются максимум шесть поздравлений и три фотографии.

Поздравления выбираются так:

1. Главное поздравление, если оно задано.
2. Следующие поздравления в порядке финальной открытки.
3. Всего не более шести элементов.

Имя автора отображается полностью. Текст превращается в короткий фрагмент до шести целых слов и всегда заканчивается многоточием. Полное поздравление в intro не воспроизводится. Пустой текст заменяется нейтральной фразой «Тёплые слова уже внутри…».

Фотографии намеренно размыты только в исходной chat-сцене, чтобы не раскрывать содержимое открытки заранее. При переносе в шаблон размытие снимается. До трёх фотографий сохраняют `object-position`, заданный кадрированием.

Качества показываются в idle-сцене как пять компактных флажков/маркеров под заголовком «За что мы тебя ценим». При сборке они переходят в текстовое оформление шаблона.

## Таймлайн полного движения

| Этап | Время от запуска | Результат |
| --- | ---: | --- |
| `highlighting-messages` | 100 мс | Выбранные поздравления визуально отделяются от шума. |
| `detaching-content` | 900 мс | Поздравления и фотографии начинают выходить из чатов. |
| `fading-noise` | 1250 мс | Невыбранное общение уходит на задний план. |
| `grouping-content` | 1550 мс | Материалы собираются в общую source-колонку. |
| `holding-content` | 2750 мс | Короткая пауза подтверждает собранный набор. |
| `revealing-preview` | 3150 мс | Появляется пустой каркас выбранного шаблона. |
| `embedding-messages` | 3700 мс | Шесть поздравлений последовательно переходят в открытку. |
| `embedding-photos` | 4750 мс | До трёх фотографий переходят в фотозону шаблона. |
| `settling` | 5350 мс | Композиция успокаивается и фиксируется. |
| `handoff` | 5800 мс | Intro передаёт управление финальной открытке. |
| `finished` | 6400 мс | Отображается обычный публичный gift-view. |

Эти отметки описывают драматургию сцены; внутренний stagger отдельных карточек и фотографий остаётся деталью компонента.

## Непрерывность переноса фотографий

Для каждой фотографии на полном motion-пути создаётся один временный DOM-overlay. Один и тот же визуальный объект проходит маршрут `chat → source-column → target-zone`, поэтому между этапами не должно быть исчезновения, подмены пустым прямоугольником или скачка кадрирования.

Клон изображения использует уже выбранный браузером `currentSrc`; `srcset` и `sizes` удаляются, загрузка переводится в eager. Перед финальным участком координаты целевой фотозоны измеряются повторно после обновления layout. После завершения overlay удаляется, а штатная фотография внутри превью становится видимой.

## Шаблоны и профили

Геометрия превью задаётся профилем, а не ветвлениями внутри runtime. Профиль связывает визуальный и motion preset шаблона с нормализованными зонами:

- `messages`;
- `photos`;
- `qualities`;
- `quotes`.

Профили определены для `paper-birthday`, `route-adventure`, `school-scrapbook`, `school-classic`, `kindergarten-doodles` и `team-editorial`. При добавлении нового шаблона необходимо одновременно подготовить профиль финальной открытки для конверта и `GiftRevealPreviewProfile` для «Собрать поздравления», затем проверить обе анимации в `/example`.

## Mobile и доступность

- Для ширин 390, 412 и 430 px используется самостоятельная вертикальная композиция, а не уменьшенная desktop-сцена.
- Фотографии остаются внутри сообщений, собираются под колонкой поздравлений и попадают в фактические target-зоны шаблона.
- Финальные расхождения overlay и target должны оставаться в пределах округления layout, без видимого скачка.
- При `prefers-reduced-motion: reduce` сложные перемещения заменяются коротким раскрытием результата. Пользователь может запросить полную анимацию явно.
- CTA и «Пропустить» доступны с клавиатуры; декоративные части сцены не добавляются в смысловое дерево.

## Хранение и миграция

Миграция `migrations/0036_gift_animation.sql` добавляет `cards.gift_animation_id text NOT NULL DEFAULT 'envelope'` и ограничивает значение вариантами `envelope` и `collect-messages`. Миграция совместима с существующими открытками: они продолжают использовать конверт.

JSON- и PostgreSQL-репозитории, сервисный слой и тип `CardDraft` сохраняют поле одинаково. Неизвестное входное значение не должно попадать в репозиторий: UI и server action используют общий валидатор `isGiftAnimationId`.

## Проверка перед выпуском

Минимальный контур:

1. `npm run typecheck`.
2. `npm run lint` — включает проверки UI-палитры и контраста.
3. `npm test`.
4. `npm run build`.
5. `git diff --check`.
6. В `/example` проверить обе анимации и все шесть профилей.
7. На 390/412/430 px проверить сценарии с 0, 1 и 3 фотографиями.
8. Убедиться, что фотография видна в исходном сообщении, сохраняется в source-колонке, становится резкой в открытке и не прыгает при завершении переноса.
9. После публикации выполнить `npm run db:migrate`, затем smoke `/manage → /gift` для обоих вариантов.

Локальные изображения, кадры и GIF из `artifacts/` являются временными QA-материалами и в Git не хранятся.
