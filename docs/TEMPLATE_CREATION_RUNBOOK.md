# Создание нового шаблона открытки

Статус: рабочая инструкция для семьи `universal-v1`.

Дата: 11 августа 2026 года.

Связанные документы:

- `UNIVERSAL_TEMPLATE_FAMILY_V1.md` — семантический и контентный контракт семьи;
- `TEMPLATE_AUTOMATION_IMPLEMENTATION_PLAN_2026-08-11.md` — история внедрения автоматизации;
- `LEGACY_TEMPLATE_BASELINE_2026-08-11.md` — зафиксированная база Paper и Route;
- `PUBLIC_SHARE_EXPORTS.md` — правила публичной страницы и скачиваемых форматов.
- `SCHOOL_SCRAPBOOK_PILOT_POSTMORTEM_2026-08-17.md` — полный разбор ошибок первого продуктового universal-шаблона и защита от повторения.

## 1. Что создаётся автоматически

Команда scaffold создаёт профиль, регистрацию, декларативный каталог ассетов и каталоги source/output. Она также добавляет шаблон в `generated-registry.ts`. Новый шаблон получает `availability: "studio"`: он автоматически появляется в справочнике шаблонов ателье и доступен в тестах и visual baseline, но не появляется в продуктовом каталоге и рабочих открытках. Слово «зарегистрирован» в продуктовом смысле используется только после двух успешных прогонов `npm run template:launch-check`: до и после перевода availability в `product`.

Справочник ателье строится из всех регистраций семейства `universal-v1`, независимо от значения `availability`. Не добавляйте ID нового шаблона вручную в компонент ателье: достаточно корректной записи в `generated-registry.ts`. `northern-light` и `daylight-proof` служат текущими контрольными примерами этого контракта.

Перевод в `availability: "product"` выполняется отдельным изменением только после визуальной приёмки пользователем и успешной проверки на реальной тестовой открытке.

Новый `universal-v1` шаблон не должен добавлять проверки своего ID в компоненты, маршруты, публичный сервис или export renderer.

## 2. Быстрый путь

Из корня проекта выполнить:

```powershell
npm run template:new -- --id=aurora-night --name="Ночное сияние"
```

Требования к ID:

- только безопасный `kebab-case`: строчные латинские буквы, цифры и дефисы;
- ID уникален и после публикации не переименовывается;
- `paper-birthday`, `route-adventure` и `universal-sandbox` зарезервированы;
- существующий каталог не перезаписывается.

Команда создаст:

```text
src/templates/aurora-night/
├── profile.ts
├── registration.ts
└── template.assets.json

template-assets/aurora-night/source/
public/templates/aurora-night/
```

Далее:

1. Поместить исходники в `template-assets/aurora-night/source/` под именами из `template.assets.json`.
2. Настроить художественные токены и asset refs в `profile.ts`.
3. Уточнить описание, рекомендации и accent каталога в `registration.ts`.
4. Выполнить команды:

```powershell
npm run template:assets
npm run template:check
npm run dev
```

5. Открыть `/template-studio/aurora-night` и пройти визуальную матрицу.
6. Получить явное подтверждение визуальной приёмки.
7. Проверить шаблон на отдельной тестовой открытке, не меняя рабочие открытки пользователя.
8. Только после этого изменить `availability` регистрации со `studio` на `product`.
9. Перед передачей выполнить:

```powershell
npm test
npm run lint
npm run template:ci
```

`template:assets` оптимизирует все объявленные каталоги и заново формирует preview. `template:check` проверяет реальные размеры, alpha-канал и бюджеты. `template:ci` дополнительно проверяет legacy-базу и все сгенерированные universal-шаблоны.

## 3. Базовый каталог ассетов

| Asset ID | Исходник | Результат | Геометрия | Alpha |
|---|---|---|---:|---|
| `page` | `page.png` | `page.webp` | `1536 × 1024` | Непрозрачный |
| `section-{block}` × 7 | `section-{block}.png` | `section-{block}.webp` | `1376 × 768` по умолчанию | Любой |
| `greeting-card-{1…4}` | PNG | WebP | `1200 × 400` | Любой |
| `quality-card` | `quality-card.png` | `quality-card.webp` | `480 × 258` | Любой |
| `quote-card` | `quote-card.png` | `quote-card.webp` | `1402 × 1122` | Любой |
| `photo-frame-portrait-base` | PNG | WebP | `802 × 1122` | Прозрачный |
| `photo-frame-portrait-overlay` | PNG | WebP | `802 × 1122` | Прозрачный |
| `photo-frame-landscape-base` | PNG | WebP | `1122 × 802` | Прозрачный |
| `photo-frame-landscape-overlay` | PNG | WebP | `1122 × 802` | Прозрачный |
| `preview` | Автоматически из указанного source asset | `preview.webp` | `1200 × 630` | Любой |

Состав можно расширять через `template.assets.json`, если новые файлы укладываются в контракт `TemplateProfile`. Пути source/output обязаны оставаться внутри каталогов своего шаблона.

Стандартные бюджеты scaffold:

- один оптимизированный файл — до `2 000 000` байт;
- суммарная загрузка — до `8 000 000` байт;
- суммарная decoded memory — до `64 000 000` байт.

Повышение бюджета не является обычной настройкой оформления: оно требует отдельного обоснования производительности и проверки мобильного устройства.

### 3.1. Контракт адаптивной подложки

Подложка блока объявляется не как произвольная картинка, а как `TemplateSectionUnderlay`: desktop-ассет, стандартный preset и при необходимости отдельный mobile-ассет. Пиксельных координат блока в профиле нет.

```ts
summary: defineSectionUnderlay(
  asset("/templates/aurora-night/section-summary.webp", 1376, 768),
  "cover",
  {
    mobileAsset: asset("/templates/aurora-night/section-summary-mobile.webp", 600, 800),
    safeArea: { x: .18, y: .1, width: .64, height: .8 }
  }
)
```

Доступны три режима:

| Preset | Для чего | Что делает renderer |
|---|---|---|
| `adaptive-frame` | Бумага, рамка, карточка с оформленными краями | Делит исходник на девять зон; углы и края сохраняются, центральные зоны адаптируются к ширине и высоте контента |
| `cover` | Спокойная текстура без значимых деталей у краёв | Заполняет весь блок с допустимой обрезкой и общей точкой фокуса |
| `bottom-edge` | Нижний орнамент или декоративная полоса | Закрепляет изображение у нижнего края, не растягивая его на весь блок |

Каждый preset централизованно задаёт:

- алгоритм масштабирования Web и Export;
- спокойную `safe text` область;
- минимальные внутренние отступы контента;
- неизменяемые срезы рамки либо высоту краевого орнамента.

В профиле шаблона разрешено выбрать preset, прозрачность и, для `cover`/`bottom-edge`, точку фокуса. Для композиции, которая не переносится между desktop и mobile без обрезки, разрешён `mobileAsset`: он должен быть самостоятельной вертикальной композицией, а не растянутой копией desktop-изображения. `safeArea` можно переопределить только нормализованным прямоугольником под спокойную зону конкретного художественного ассета; отдельные координаты текста всё так же запрещены. Размеры nine-slice-срезов остаются стандартом семейства и не настраиваются в профиле.

Каждый семантический блок получает собственный `section-{block}`. Повторное использование одного файла во всех семи блоках допустимо только для технической диагностики nine-slice и не считается визуальной приёмкой шаблона. Базовый формат scaffold — `1376 × 768`; его можно уменьшить при сохранении пропорции, если decoded-memory матрица остаётся слишком тяжёлой.

Для `adaptive-frame` значимые углы располагаются в крайних 5%, декоративные верх/низ — в крайних 8%, центральная область должна допускать растяжение. Для `cover` значимый декор нельзя размещать за пределами области, которая останется видна после кадрирования. Если это невозможно, делается отдельный `mobileAsset` или панорамный desktop-ассет. В спокойной области нельзя размещать текст, логотипы, лица и мелкие неповторяемые детали.

Карточки поздравлений используют ровно четыре отдельные адаптивные подложки `greeting-card-1…4`. Renderer назначает их по кругу `0 → 1 → 2 → 3 → 0`, в том числе в модальном окне. Края сохраняются nine-slice-механикой, а автор и текст располагаются внутри общей safe-area; отдельные координаты для каждой карточки запрещены.

### 3.2. Контракт фоторамок без ручной подгонки

Фоторамка выбирает один из двух общих preset-ов. Профиль шаблона не содержит собственных `aperture`, `captionArea` или `aspectRatio`:

| Preset | Размер ассетов base/overlay | Окно фото | Область подписи |
|---|---:|---|---|
| `portrait-polaroid` | `802 × 1122` | `8% · 5% · 84% · 76%` | `8% · 83% · 84% · 11%` |
| `landscape-polaroid` | `1122 × 802` | `8% · 7% · 84% · 70%` | `8% · 80% · 84% · 14%` |

Ассеты основы и верхнего слоя должны точно соответствовать размеру выбранного preset-а. Проверка профиля отклоняет несовпадающий размер. Пользовательская фотография всегда заполняет стандартное окно через `cover`, а crop/zoom обрезается внутри `aperture` и физически не может выйти на рамку или подпись.

### 3.3. Контракт текстовых плашек

Карточки качеств и лучших фраз тоже используют общие preset-ы вместо ручных координат:

| Preset | Размер ассета | Safe text |
|---|---:|---|
| `quality-pill` | `480 × 258` | `5% · 10% · 90% · 80%` |
| `quality-pill-export` | `720 × 180` | `7% · 12% · 86% · 76%` |
| `quote-panel` | `1402 × 1122` | `5,5% · 28% · 89% · 62%` |

Динамический текст размещается только внутри preset-области. Ателье показывает границы рамки/плашки, окна фотографии и safe text, но не предлагает отдельную попиксельную настройку для каждого шаблона.

Если художественная форма `quality-pill` становится слишком мелкой в фиксированной экспортной сетке `2–1–2`, профиль может объявить полный `exportQualityCards` из пяти карточек preset-а `quality-pill-export`. Средняя карточка центрируется, а пары первой и третьей строк разделяются интервалом шириной в одну карточку. Этот набор используется только Story/Post/A4; Web продолжает использовать `qualityCards`. Экспортные карточки должны быть самостоятельной горизонтальной композицией, а не растянутой копией web-ассета.

### 3.4. Контракт ёмкости текста

Бирюзовая линия `Жёсткий лимит текста / подпись` показывает максимальный контейнер, а не фактическую высоту короткого текста. Его размеры не меняются от текущего содержимого. Общие presets находятся в `src/lib/templates/text-capacity-presets.ts` и одинаково применяются в Web и Export:

| Область | Жёсткий предел | Поведение переполнения |
|---|---:|---|
| Имя получателя | целевой universal-v1 лимит 46 символов, совместимость с текущим продуктовым вводом до 80, 2 строки | три ступени размера шрифта; многоточие только для аномальной длины и совместимости со старыми данными |
| Поздравление в блоке | 5 строк в карточке | многоточие; сохранённый полный текст до 1500 символов остаётся в модальном окне |
| Подпись фотографии | 45 символов, 2 строки | обрезка внутри `captionArea` |
| Качество | 28 символов, 2 строки | обрезка внутри preset-области плашки |
| Лучшая фраза | целевой диапазон 55–80, жёсткий максимум 100 символов, 4 строки | обрезка внутри preset-области карточки |

Переносы строк не увеличивают блок: последовательности пробелов и переносов обрабатываются обычным потоком текста, а высота ограничена preset-ом. Значения `200`, `280` и `340` — рекомендации для компактного вида конкретной схемы, а не предел хранения. Поздравление сохраняется целиком до общего лимита 1500 символов; в карточке действует line-clamp, а в модальном списке полный текст выводится без него.

### 3.5. Ателье — источник истины

Любая шаблонная геометрия, ассет, crop, nine-slice, horizontal-slice, typography-token или правило видимости сначала описывается в профиле `universal-v1` либо в общем renderer/preset и проверяется в ателье. Продуктовые private/public-страницы и Story/Post/A4 не получают отдельные координаты или скрытые исключения по `templateId`: они только подставляют реальные данные в тот же профиль.

Экспортный preview ателье и продуктовый export обязаны использовать единый resolver `resolveTemplateExportAsset`. Параметры `crop`, `width`, `height` и `slices` исполняются через `/api/template-export-asset`; прямая передача сырого URL `/templates/...?...` запрещена, потому что статическая раздача файла игнорирует эти преобразования и деформирует ассет при заполнении контейнера.

Допустимые различия между поверхностями остаются декларативными и видимыми в ателье: например, `mobileAsset`, `exportQualityCards`, `visibleOn`, форматный preset или отдельная композиция public. Код продуктового route может адаптировать payload и абсолютный origin, но не определять художественную геометрию шаблона.

Правка шаблона не считается завершённой, пока одновременно не выполнены три условия:

1. Private/public и Story/Post/A4 выглядят правильно в ателье.
2. Реальная открытка использует тот же профиль без локальных координат и ветвлений по ID.
3. Скачанные PNG/PDF совпадают с preview ателье по crop, пропорциям, декору и композиции.

### 3.6. Независимая экспортная геометрия декора

Каждый декоративный слой с `visibleOn`, содержащим `export`, обязан объявлять полный набор `exportVariants.story/post/a4`. Для каждого формата независимо задаются `rect`, а при необходимости `opacity` и `rotation`. Ателье создаёт три варианта вместе с новым слоем, но исходные одинаковые значения считаются только стартовой точкой: Story, Post и A4 проверяются и настраиваются отдельно.

Экспортный декор может выходить за границы шапки или своей семантической секции. Нормализованные `x`/`y` допускают отрицательное положение, а ширина и высота экспортного варианта — размер до `3×`. Семантическая секция не обрезает такой слой; окончательное ограничение выполняет только корневой холст скачиваемого файла. Это позволяет доске, букету или другому крупному предмету продолжаться в соседнюю свободную область без изменения Web/mobile-композиции.

Обязательные правила:

- нельзя исправлять Story/Post/A4 изменением общей Web-геометрии слоя;
- отсутствие хотя бы одного из трёх экспортных вариантов является ошибкой валидации профиля;
- положение, масштаб, прозрачность и поворот настраиваются в инспекторе выбранного формата ателье;
- значимые предметы подложки нельзя растягивать вместе с пустым центром: для панорамного подвала используется `horizontal-slice` с защищёнными краями, а растяжимой остаётся только спокойная центральная зона;
- preset и палитра счётчиков задаются в профиле один раз и применяются одинаково в Web-открытке и Story/Post/A4.

## 4. Художественный чек-лист

- [ ] Визуальная идея оригинальна, источник и способ создания зафиксированы; для AI-ассетов сохранён финальный prompt.
- [ ] Растровые ассеты не содержат текста, букв, логотипов, водяных знаков и элементов управления.
- [ ] На фонах есть спокойные зоны для имени, длинного поздравления и подписей; декор не конкурирует с пользовательским содержимым.
- [ ] Контраст `text`, `muted` и `accent` проверен на каждой section surface и на реальном изображении, а не только на цветном прямоугольнике.
- [ ] Художественная палитра остаётся внутри открытки. Коричневый, кофейный, сепия и терракотовый не переносятся в каталог, менеджер, кнопки или другие UI-элементы.
- [ ] Portrait и landscape рамки имеют реальную прозрачность, корректное окно `aperture` и отдельную безопасную область `captionArea`.
- [ ] Подпись длиной 45 символов помещается полностью в две строки без многоточия и без наложения на фотографию.
- [ ] Детали сохраняются после WebP-оптимизации; нет цветовых полос, грязных прозрачных краёв и заметных артефактов ресайза.
- [ ] Preview узнаваем на узкой карточке каталога и не зависит от мелких деталей.
- [ ] Исходники воспроизводимы: ручные слои сохранены либо производные файлы собираются отдельным скриптом, как в пилоте `northern-light`.

## 5. Визуальная приёмка

Для private mobile отдельно проверить блоки `messages` и `memories`: `adaptive-frame` использует мобильную nine-slice-рамку без растянутого центра, а `cover` с важным декором переключается на `mobileAsset`. В обоих случаях подложка не должна менять пропорции, скрывать края рамок или создавать горизонтальный overflow. В `messages` художественные рамки также остаются на четырёх видимых карточках и фоторамках. Порядок — счётчик, фото, четыре поздравления, нижняя кнопка полного списка. Оба триггера открывают один диалог и возвращают пользователя к месту открытия. Подвалы private и public на mobile/desktop обязаны использовать одну подключаемую `sections.closing`; различается только смысловой контент.

В `/template-studio/[templateId]` проверить:

| Область | Обязательные состояния |
|---|---|
| Web private | Desktop/mobile; все шесть схем `grid-2`, `carousel-1`, `carousel-2`, `portrait`, `landscape-pair`, `landscape-trio`; desktop без фото сохраняет сетку 2×2 / один ряд из 3 / два ряда по 3 и прокручивается штатной горизонтальной полосой со snap по одному столбику |
| Web public | Desktop/mobile; безопасный порядок блоков; нет summary, поздравлений участников и private signature |
| Фотографии | 0, 1, 2 и 3 фото в поздравлениях; блок «Моменты» независимо сохраняет собственные три фото; crop одинаков на всех поверхностях |
| Тексты | Короткие, обычные и предельные; имя 46, подпись 45, качество 28, фраза 100, главное поздравление 500 символов |
| Необязательные блоки | Полный состав и отсутствие qualities/memories/quotes без пустых контейнеров |
| Export | Story `1080 × 1920`, Post `1080 × 1350`, A4 `1240 × 1754`; счётчики поздравлений и фото совпадают с public; качества `2–1–2`; «Моменты» — крупное фото + правая колонка; 3/2/3 фото и 2/3/3 лучших фразы соответственно |
| Export paper | Заголовок и описание блока полностью лежат на одной подложке; листы подписей заходят на фото, не оставляют белого паспарту и вмещают две строки во всех трёх форматах |
| Intro | Только лёгкие intro-токены; тяжёлый page asset не загружается |

Для каждого состояния проверить:

- [ ] нет горизонтального overflow и внутренней прокрутки текста;
- [ ] подписанные линии `подложка` и `safe text` различимы; текст не пересекает safe text, края, декор и окна фотографий;
- [ ] нет битых изображений и ошибок браузера;
- [ ] текст читаем, не обрезан и не скрыт многоточием там, где контракт требует полный вывод;
- [ ] mobile сохраняет смысловую иерархию, а не только уменьшает desktop;
- [ ] при включённом `motion.revealSections` секции появляются один раз и не проигрываются повторно после обратной прокрутки;
- [ ] hover применяется только при `(hover: hover) and (pointer: fine)`, а touch-отклик не создаёт ложной кликабельности у статичных карточек;
- [ ] при `motion.photoViewer` фотография открывается по click/tap, листается стрелками и свайпом, закрывается по `Escape`, после закрытия фокус возвращается на исходный элемент;
- [ ] при `prefers-reduced-motion: reduce` весь контент сразу видим, необязательные перемещения и масштабирование отключены;
- [ ] публичная страница и exports не содержат приватных данных;
- [ ] preview ателье и скачанное изображение используют общий resolver ассетов; `crop`/`slices` действительно применены, а не оставлены query-параметрами сырого статического URL;
- [ ] preview скачивания совпадает со скачанным изображением по renderer, crop, пропорциям и композиции;
- [ ] каждый export-visible слой имеет отдельные Story/Post/A4-варианты; декор может выйти из шапки, но не из корневого холста;
- [ ] счётчики используют один профильный preset в Web и Export;
- [ ] контрольные скриншоты просмотрены после `npm run template:universal-baseline`;
- [ ] отчёт `screenshots/template-universal-baseline/report.json` не содержит failures.

## 6. Когда нужна новая структурная семья

Новое оформление остаётся в `universal-v1`, если меняются только ассеты, цвета, разрешённые шрифты, поверхности, фоторамки, декларативный декор и выбор общего motion-preset `calm`/`playful`.

Новая семья требуется, если хотя бы одно необходимое продуктовое отличие нельзя выразить текущим профилем без:

- нового порядка или смысла обязательных блоков;
- нового контентного контракта или другого набора приватных/публичных данных;
- нового количества фотографий в структурной композиции;
- произвольного React/HTML/CSS или callback в профиле;
- проверки конкретного `templateId` в общем renderer, service или route;
- отдельного export renderer, который не может использовать общую модель и рамки семьи.

Порядок создания семьи:

1. Описать семантику, поверхности, content/privacy contract, responsive и export-матрицу отдельным versioned-документом.
2. Добавить новый discriminator семейства, runtime-валидацию профиля и регистрацию.
3. Реализовать один web renderer и один fixed-canvas export renderer для всей семьи.
4. Добавить fixture-граничные состояния, публичный адаптер и visual regression до первого художественного шаблона.
5. Только после этого создать пилотный профиль и подключить его через генератор.

Запрещено объявлять новую семью только ради цвета, фона, другой формы рамки или единичного исключения в композиции.

## 7. Решение по Paper и Route

`paper-birthday` и `route-adventure` остаются в семье `legacy`. Их перенос не нужен для добавления новых шаблонов и не входит в автоматизацию `universal-v1`.

Миграцию можно рассматривать только как самостоятельный продуктовый редизайн при одновременном выполнении условий:

- есть измеримая пользовательская или эксплуатационная выгода, которую нельзя получить legacy-поддержкой;
- новая версия сохраняет совместимость уже созданных открыток и публичных ссылок либо имеет утверждённую миграцию данных;
- до переключения пройдена полная матрица `LEGACY_TEMPLATE_BASELINE_2026-08-11.md` и визуальное сравнение принято вручную;
- rollout допускает мгновенный возврат к legacy renderer.

До такого отдельного решения нельзя менять их композицию, маршрутизацию, export-ветку или идентификаторы в рамках работы над новыми universal-шаблонами.

## 8. Готовность к передаче

Шаблон считается готовым к переводу из `studio` в `product`, когда:

- его профиль проходит runtime-валидацию и тест регистрации;
- все объявленные source-ассеты присутствуют и `template:check` проходит без исключений бюджета;
- он виден в каталоге и менеджере из общих метаданных;
- ателье открывает именно зарегистрированный профиль;
- private/public и Story/Post/A4 проходят интеграционные тесты;
- universal visual baseline проходит без overflow, битых изображений и browser errors;
- полный `npm test`, `npm run lint` и `npm run template:ci` успешны;
- в общих поверхностях не появилось ветвлений по ID нового шаблона;
- legacy-baseline Paper/Route остался зелёным.
- пользователь явно принял визуальный результат;
- переключение на шаблон и обратно проверено на отдельной тестовой открытке без ошибок менеджера.
- `npm run template:launch-check` прошёл после переключения в `product`; product-шаблон автоматически найден в каталоге, dispatcher, intro и всех export-форматах.

### Единственная команда допуска

```powershell
npm run template:launch-check
```

Она объединяет asset/legacy/universal проверки, полный `npm test` и production build. Universal baseline включает не только Web, но и реальные холсты Story/Post/A4: проверяет размеры, page underlay, closing slice, transform-route, broken images и browser errors. Ручной набор выборочных тестов не заменяет эту команду.

## 9. Обязательный launch-gate после пилота `school-scrapbook`

Ателье проверяет геометрию профиля, но не заменяет полный продуктовый сценарий. До первого реального теста следующего шаблона нужно создать отдельную открытку с настоящими данными и пройти цепочку целиком. Пилот школьного шаблона выявил блокировки, которые не были видны в изолированном предпросмотре: каталожный preview и выбранная миниатюра могли расходиться; preview черновика открывал legacy-разметку; `studio`-доступность блокировала передачу; публичный payload не проходил ограничение версии; дата и финальная подпись не сохранялись; дата сдвигалась из-за UTC; устаревшие AI-блоки ошибочно запрещали передачу; WebP-ассеты падали в `ImageResponse`; `minScale` подписи применялся как постоянное уменьшение.

Перед переводом `availability` в `product` обязательны:

- [ ] каталог, выбранный шаблон, intro и preview черновика используют один `templateId` и одну регистрацию;
- [ ] private desktop/mobile открываются из реальной переданной открытки, а не только из fixture ателье;
- [ ] публичный черновик создаётся, сохраняется и повторно открывается с актуальной версией payload;
- [ ] событие, дата, подпись и дополнительные настройки сохраняются после обновления страницы; календарная дата не проходит через UTC-преобразование;
- [ ] существующие качества и фразы можно оставить без повторной AI-генерации и передать с предупреждением;
- [ ] режим доступности шаблона допускает тестовую передачу до общего продуктового выпуска;
- [ ] одинаковые реальные подписи фото имеют одинаковый scale в ателье, private и public; `minScale` используется только около лимита 45 символов;
- [ ] все четыре export URL возвращают `200` и правильный `Content-Type`: Story PNG, Post PNG, Print preview PNG, Print PDF;
- [ ] серверный экспорт принимает оптимизированные WebP/AVIF ассеты профиля через общую конвертацию, без ручных PNG-копий конкретного шаблона;
- [ ] в скачанных Story/Post/A4 видны page/section underlay, нет чёрных или прозрачных прямоугольников; nine-slice/horizontal-slice проверены именно после серверной сборки в единый PNG;
- [ ] прозрачные hero/qualities/quotes в экспортном макете не завернуты в общую позиционируемую surface-обёртку: для `ImageResponse` они рендерятся прямыми flex-секциями, иначе композитный слой может оказаться в левом верхнем углу холста;
- [ ] админка находит тестовую открытку без ограничения последней неделей и позволяет выдать/отозвать бесплатный приватный доступ;
- [ ] в журналах после полного прохода нет `404`, `500`, constraint violations, unsupported image type и блокировок по ID шаблона.

Минимальная проверка экспортных маршрутов на реальном публичном токене:

```powershell
curl.exe -I http://localhost:3000/share/{token}/image/story
curl.exe -I http://localhost:3000/share/{token}/image/post
curl.exe -I "http://localhost:3000/share/{token}/image/print?preview=1"
curl.exe -I http://localhost:3000/share/{token}/image/print
```

Перевод в `product` выполняется только после этого прохода. После изменения availability полный `template:launch-check` запускается повторно. Успех unit-тестов рендера с замоканным `ImageResponse` сам по себе недостаточен: нужен хотя бы один настоящий серверный raster/PDF render с реальными ассетами профиля.
