## Приоритет 1. Telegram-превью приглашения

Production уже проверен с User-Agent TelegramBot: HTML действующего `/join` содержит абсолютное шаблонное `og:image`, `twitter:card=summary_large_image`, noindex; статический PNG отвечает 200. Значит, наиболее вероятен сохранённый Telegram результат старого URL, который раньше не имел шаблонного OG.

У публичной `/share` уже используется параметр версии `?preview=v1`; копирование и native share приглашения `/join` передают неизменный URL. Нужно:

1. Добавить единую функцию версии invitation URL, например `preview=join-v2`, сохраняя другие query-параметры.
2. Использовать её в `CopyLinkButton`, `ShareLinkButton`, тексте приглашения и местах, где показывается готовая ссылка для отправки; canonical оставить чистым `/join/{slug}`.
3. Дополнить тесты копирования, native share и metadata. Не включать в URL секреты кроме уже существующего public slug.
4. Проверить HTML и PNG с User-Agent TelegramBot, выполнить обычный релизный контур.
5. После деплоя владелец отправляет новый versioned URL в Telegram. Если картинки снова нет, получить скриншот, точный способ отправки и проверить настройки/бота предпросмотра Telegram.

## Приоритет 2. Локальная очистка

Сначала перечитать `LOCAL_WORKSPACE_CLEANUP_2026-08-26.md`. После явного подтверждения владельца удалить только `.next/`, `.npm-cache/`, `tmp/`, `screenshots/`: ожидаемая экономия около 4,00 GiB. `node_modules/` удалять отдельно только если допустима последующая переустановка; это ещё 466,29 MiB.

Не использовать `git clean -X`: он затронет `.env.local`, `key.txt`, `data/`, `public/uploads/`, ручной PDF и референсные PNG.

Удалить шесть неиспользуемых `kindergarten-doodles/quote-card-*-export` PNG/WebP после повторной проверки ссылок. Ожидаемая экономия меньше 0,2 MiB; цель — убрать несогласованный мусор, а не освободить диск. Обновить три упоминания в документации и запустить `npm run template:check`.
