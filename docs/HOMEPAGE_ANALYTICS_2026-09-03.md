# Аналитика главной и рекламных источников

Реализовано локально 3 сентября 2026. Для начала сбора на slovesto.ru нужна выкладка кода. Новых переменных окружения и миграций нет. Более ранние посещения главной не восстанавливаются.

## Что видно в `/admin/analytics`

- «Главная и тематические страницы»: просмотры, нажатия «Пример» и «Создать», созданные и оплаченные открытки для главной и четырёх тематических страниц.
- «Что нажимают на главной»: шапка/мобильное меню, первый экран, шаблоны, цена, нижний блок и подвал.
- «Источники созданных открыток»: первая сохранённая страница входа, источник, канал, кампания и результат открытки. Отдельно показано число открыток с определённым и неопределённым источником.

Периоды — 7 и 30 дней. Просмотры и нажатия считаются как события; это не уникальные посетители, сессии или только первые входы. Повторное открытие страницы увеличивает число просмотров. Нажатия не доказывают создание. Отношение всех нажатий/просмотров к открыткам с сохранённым источником не является корректной конверсией: охват согласия, временные периоды и единицы учёта отличаются. Конверсия создания в оплату по-прежнему рассчитана по когорте уникальных открыток.

В таблице источников нет посетителей, которые не создали открытку, и нет расходов из рекламных кабинетов. Неопределённый источник не маркируется как прямой трафик. Поисковые роботы с JavaScript могут увеличивать счётчики; блокировщики, отключённый JavaScript и сетевые ошибки могут уменьшать их.

## Как размечать ссылки

Пример ссылки для публикации в Telegram:

```text
https://slovesto.ru/?utm_source=telegram&utm_medium=social&utm_campaign=teacher_september
```

Используются `utm_source`, `utm_medium`, `utm_campaign`. Выбирайте устойчивые короткие названия каналов и кампаний, без имён, email, телефонов, секретных ссылок и других пользовательских данных. Для другого размещения меняйте кампанию или источник. `utm_content`, `utm_term` и рекламные click ID не сохраняются.

После согласия cookie `slv_first_touch` сохраняет первый доступный источник до 90 дней. Переход через пример, `/create`, `/manage/new` или тематическую страницу не заменяет существующую первую кампанию. Создание переносит её в `funnel.card_created`, затем серверный отчёт связывает её с подтверждёнными платежами. Если согласие дано позднее на другой странице, первоначальный вход без согласия не восстанавливается.

## События и согласие

Новые `home_page_view`, `home_example_click`, `home_create_click` используют существующий `/api/telemetry`. Клиент отправляет их без cookie и HTTP Referer. Сервер разрешает только фиксированную пару `home` / `/` и шесть названий блоков. В событиях нет ID посетителя/открытки, IP, UTM, referrer или пользовательского текста. Сохраняются запись события с её собственным ID, время, тип и блок страницы; админка суммирует записи. Защита API от частых запросов по-прежнему использует кратковременный хеш IP в памяти, отдельно от журнала событий.

UTM/referrer и cookie атрибуции появляются только после согласия. Метрика по-прежнему получает URL без query-параметров; новые рекламные источники отображаются в собственной админке, интеграция UTM-отчётов Метрики не расширялась.

Контроллер согласия перенесён из общего подвала в корневой layout. Баннер доступен на главной и четырёх тематических страницах, а переход на остальные страницы приостанавливает Метрику. Исправлено удаление сохранённого первого источника при первоначальном чтении согласия. Отказ в другой вкладке также останавливает счётчик и очищает доступные аналитические идентификаторы. Политика дополнена фактическим описанием счётчиков главной; состав данных, передаваемых Яндексу, и условия действующего согласия не расширялись.

## Проверено

- 66 тестов в десяти затронутых наборах: главная, рекламный источник, согласие/отказ, переходы, серверное создание, отчёт и фильтрация полей.
- Отдельно 13 тестов PostgreSQL, включая кампанию главной → созданную открытку → подтверждённую оплату. Только временные таблицы и rollback; данные приложения не изменяются.
- TypeScript, production build, lint, UI colors и UI contrast прошли. Lint сообщает два существующих предупреждения о `<img>` в `public-share-panel.tsx`.
- В локальном браузере проверены главная, баннер, отказ и переход к примеру. Отчёт проверен компонентными тестами; для просмотра в локальном браузере требуется вход администратора.
